# 监听与 APP 形态策略

## 1. 当前两个显示形态

### 桌面控制台

入口：

```text
http://127.0.0.1:5173
```

用途：

- 查看所有监听实例。
- 调试事件。
- 保留模拟状态按钮，方便没有真实软件事件时测试 UI 和语音。
- 后续桌面应用会在这里扩展设置、适配器管理、语音规则、局域网配对。

### 手机/副屏状态屏

入口：

```text
http://127.0.0.1:5173?display=1
```

默认是浅色 APP 界面。点击像素小人后切换到 OLED 专注模式：

- 这是 APP 内的第二页面，适合作为常驻展示页。
- 页面背景为纯黑，适合 OLED 屏幕常亮。
- 大屏/横屏时左边是放大的像素小人，右边是实时状态和调用日志。
- 竖屏手机上保持上方小人、下方状态，避免拥挤。
- 页面内可以进入浏览器全屏，也可以退出全屏。
- 左右滑动切换当前查看的监听实例。
- 语音播报不跟随当前查看实例，而是播报所有监听工具的新事件。

## 2. 语音策略

### 播报

当前策略：

- 每个新事件都会进入播报队列。
- 不再只播报“完成”。
- 连续状态会依次播报，例如：思考中、写代码、测试、完成。
- 同一个事件 ID 只播一次，避免重复。

后续建议：

- 添加播报等级：全部事件、关键事件、只播问题和完成。
- 添加冷却规则：同一项目同一状态在 N 秒内不重复播。
- 添加夜间静音。
- 添加“只播当前滑到的工具 / 播所有工具”开关。

### 唤醒词

建议分两阶段：

1. 浏览器/手机 Web 原型：使用按钮触发播报或一次性语音查询，因为浏览器常驻唤醒词能力受系统和权限限制。
2. 原生 APP / 桌面端：接入系统语音识别或唤醒词引擎。

可选唤醒词方案：

- 桌面端：Windows Speech Recognition / Whisper 本地服务 / openWakeWord。
- 手机端：原生 iOS/Android 语音能力，或只做按住说话。
- 唤醒词示例：`Hello Code`。

唤醒后默认回答：

```text
当前活跃任务是：Claude Code 正在写代码，项目 mengbi，正在处理 Settings 页面。
```

当前 Web 原型已支持：

- 语音播报开关。
- 播报当前状态。
- 点击“语音问答”后进行一次性语音识别，浏览器不支持时降级为播报当前状态。

正式 APP 需要补：

- 常驻唤醒词，例如 `Hello Code`。
- 后台/锁屏策略。
- 麦克风权限引导。
- 只播当前查看工具 / 播所有工具的开关。

## 3. 监听策略

### 最理想：官方 Hook / 官方扩展

适合：

- Claude Code
- Codex
- 有官方插件 API 的编辑器

优点：

- 实时性高。
- 状态细节准确。
- 能知道思考、工具调用、写文件、测试、等待权限、停止等事件。

当前状态：

- Claude Code hooks 已安装到 `%USERPROFILE%\.claude\settings.json`。
- Codex hooks 已安装到 `%USERPROFILE%\.codex\hooks.json`。
- Codex 需要在 Codex 内运行 `/hooks`，信任新 hook 后才会开始执行。

### VS Code / Cursor / Windsurf

如果 Codex 或 Claude Code 是作为 VS Code 插件运行：

- 如果插件本身走 Claude Code/Codex CLI，并读取对应全局 hooks，那么优先监听 Claude Code/Codex。
- 如果要监控编辑器整体行为，则还需要 VS Code 扩展。

建议同时做两层：

1. Agent 层：Claude Code/Codex hooks，监听 AI 任务生命周期。
2. Editor 层：VS Code/Cursor 扩展，监听文件保存、终端、任务、诊断错误。

这样可以判断：

- AI 正在写代码。
- 编辑器正在保存文件。
- 测试任务正在跑。
- 当前工作区有报错。

### 国产 Code 软件

要做到“别人即开即用”，需要分级监听：

1. 优先识别是否基于 VS Code/Electron。
   - 如果兼容 VS Code 扩展，安装同一个扩展。
2. 如果有官方插件系统。
   - 为它写专用 adapter。
3. 如果没有插件系统。
   - 用通用弱监控：
     - 进程名。
     - 窗口标题。
     - 工作区文件变化。
     - 终端命令。
     - 系统通知。
     - OCR / 无障碍树读取状态文字。

建议产品内置“适配器商店”：

- Claude Code Adapter
- Codex Adapter
- VS Code Compatible Adapter
- JetBrains Adapter
- Generic Process Adapter
- OCR Adapter

用户安装后，软件自动扫描：

- 正在运行的 code 软件。
- 常见配置目录。
- 当前打开窗口。
- 是否能安装/启用对应 adapter。

## 4. 模拟状态是否还需要

需要，但只应保留在桌面调试界面，不应该出现在手机状态屏。

用途：

- 新皮肤测试。
- 语音规则测试。
- 没有打开真实 code 软件时演示。
- 开发 adapter 时调试事件格式。

最终产品里它应该藏到“开发者/调试”页面。

## 5. 手机测试方式

电脑和手机连同一个 Wi-Fi。

电脑打开桌面控制台：

```text
http://127.0.0.1:5173
```

手机打开局域网地址，例如：

```text
http://192.168.2.2:5173?display=1
```

如果打不开：

- 检查电脑防火墙是否允许 Node/Vite 入站。
- 检查手机是否和电脑在同一个网络。
- 用电脑终端确认 Vite 输出的 Network 地址。

## 6. 下一步开发建议

1. 做 VS Code/Cursor 扩展，监听编辑器层状态。
2. 给手机状态屏加设置：播报全部 / 播报当前 / 静音。
3. 做桌面悬浮小人窗口，只显示像素小人，不显示状态面板。
4. 做 adapter 自动扫描和安装引导。
5. 做语音唤醒词原型。
